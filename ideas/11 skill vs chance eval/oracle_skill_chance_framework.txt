# Oracle: Skill vs. Chance Analysis Framework

## Executive Summary

This document proposes a comprehensive methodology to evaluate where Oracle falls on the spectrum between pure chance and pure skill games. The approach combines two complementary research methodologies:

1. **Relative Skill Opportunity (RSO)** - Dreef et al. (2023)
2. **Pairwise Rating Comparison** - Duersch et al. (2018)

## Research Paper Summaries

### Paper 1: Dreef et al. (2023) - Relative Skill Opportunity

**Core Concept**: Skill opportunity is measured by comparing game outcomes when:
- All players have equal skill (homogeneous)
- Players have different skill levels (heterogeneous)

**Formula**:
```
RSO = (Var[X|heterogeneous] - Var[X|homogeneous]) / Var[X|homogeneous]

Where X = outcome metric (e.g., final score, win/loss)
```

**Interpretation**:
- RSO ≈ 0: Pure chance (skill doesn't affect outcomes)
- RSO ≈ 1: Significant skill influence
- RSO > 1: Very high skill influence

**Key Insight**: If skilled players consistently produce different outcomes than unskilled players (beyond random variation), the game has skill opportunity.

### Paper 2: Duersch et al. (2018) - Pairwise Rating Method

**Core Concept**: Use rating systems (Elo/Bradley-Terry) to:
1. Assign ratings to players based on match history
2. Predict match outcomes based on rating differences
3. Compare predictions to actual outcomes

**Formula**:
```
P(A beats B) = 1 / (1 + 10^((Rating_B - Rating_A) / 400))
```

**Metrics**:
1. **Rating Stability**: Do ratings converge and remain stable?
2. **Predictive Power**: Do ratings accurately predict match outcomes?
3. **Discrimination**: Can the system distinguish between skill levels?

**Key Insight**: If a rating system accurately predicts outcomes, skill dominates. If outcomes remain highly unpredictable despite ratings, chance dominates.

### Game Characteristics Relevant to Skill-Chance Analysis

**Chance Elements in Oracle**:
1. Initial deck distribution (Random mode)
2. Card draw order (shuffled deck)
3. Dice rolls in combat (d4, d6, d8, d12, d20)
4. Opponent's hidden hand

**Skill Elements in Oracle**:
1. Resource management (lunas)
2. Card selection (which champions to play)
3. Combat decisions (attack/defend/decline)
4. Combo construction (species/order/color matching)
5. Hand management (draw vs. play)
6. Timing (when to attack aggressively vs. conservatively)
7. Opponent modeling (predicting opponent's strategy)

**Complexity Factors**:
- Deck type affects skill ceiling (Random < Monochrome < Custom < Draft)
- Game length (longer games may allow more skill expression)
- AI sophistication (Random AI vs. Balanced vs. MCTS)

## Methodology 1: Relative Skill Opportunity (RSO)

### Implementation Strategy

#### Step 1: Define Player Skill Levels

Create a spectrum of AI strategies representing different skill levels:

1. **Keeper** (Baseline, Rating = 50)
   - Random strategy with minor improvements
   - Serves as reference point

2. **Novice** (Rating ≈ 40-45)
   - Pure Random AI
   - No strategic decisions

3. **Intermediate** (Rating ≈ 55-65)
   - Balanced Rules AI
   - Basic heuristics

4. **Advanced** (Rating ≈ 70-85)
   - Heuristic AI with lookahead
   - Power calculations

5. **Expert** (Rating ≈ 90-99)
   - Monte Carlo or IS-MCTS
   - Deep search

#### Step 2: Simulation Design

**Homogeneous Matches** (Equal Skill):
```
For each skill level S:
  Run 10,000 games of S vs. S
  Record outcomes: wins, turns, final energies
```

**Heterogeneous Matches** (Different Skill):
```
For each pair (S1, S2) where S1 > S2:
  Run 10,000 games of S1 vs. S2
  Record outcomes
```

#### Step 3: Outcome Metrics

Define measurable outcomes X:

1. **Binary Win/Loss** (primary)
   - X = 1 if Player A wins, 0 otherwise
   - Var[X] = variance of win rate

2. **Energy Differential** (secondary)
   - X = (Energy_A - Energy_B) at game end
   - Captures margin of victory

3. **Turn Count** (tertiary)
   - X = number of turns until game end
   - Faster victories may indicate skill dominance

4. **Advantage Trajectory** (advanced)
   - Track energy differential over time
   - Measure divergence point

#### Step 4: Calculate RSO

```
For each outcome metric X:

  1. Calculate Var[X|homogeneous]:
     - Pool all homogeneous matches (S vs. S)
     - Calculate variance of X across all games
     
  2. Calculate Var[X|heterogeneous]:
     - Pool all heterogeneous matches (S1 vs. S2)
     - Calculate variance of X across all games
     
  3. RSO = (Var[X|hetero] - Var[X|homo]) / Var[X|homo]
```

**Expected Results**:
- High RSO (>0.5): Skill matters significantly
- Medium RSO (0.2-0.5): Balanced skill-chance mix
- Low RSO (<0.2): Chance dominates

## Methodology 2: Pairwise Rating Comparison

### Implementation Strategy

#### Step 1: Implement Bradley-Terry Rating System

*(You already have a specification for this in `ideas/rating system/`)*

**Key Components**:
1. Rating calculation (Bradley-Terry model)
2. Match outcome prediction
3. Rating updates after each match
4. Convergence detection

#### Step 2: Simulation Design

**Rating Calibration Phase**:
```
For each AI strategy S:
  Initialize rating = 50 (Keeper baseline)
  
For 5,000 matches (random pairings):
  Select two strategies S1, S2
  Play match
  Update ratings based on outcome
  
Continue until ratings converge (change < 1 per 100 games)
```

**Prediction Testing Phase**:
```
For each rating-stabilized strategy pair (S1, S2):
  Calculate predicted win probability P(S1 beats S2)
  Play 10,000 matches
  Record actual win rate
  Compare predicted vs. actual
```

#### Step 3: Metrics

1. **Predictive Accuracy**
   - Mean Absolute Error (MAE)
   - Root Mean Square Error (RMSE)
   - Brier Score

2. **Rating Spread**
   - Range of ratings (max - min)
   - Standard deviation of ratings
   - Rating separation between adjacent skill levels

3. **Consistency**
   - Do higher-rated players consistently beat lower-rated?
   - Percentage of upsets (lower-rated wins)

**Formulas**:
```
MAE = (1/N) * Σ|P(predicted) - P(actual)|

Brier Score = (1/N) * Σ(P(predicted) - outcome)²

Consistency = % of matches where higher-rated player wins
```

#### Step 4: Compare Against Pure Chance/Skill Baselines

**Pure Chance Baseline**:
- All ratings should cluster around 50 (Keeper)
- Predictions should be ~50% regardless of pairing
- MAE should be high (~0.5)

**Pure Skill Baseline**:
- Ratings should spread widely (e.g., 10 to 90)
- Predictions should be accurate (MAE < 0.05)
- Consistency should be very high (>95%)

**Oracle's Position**:
- Compare Oracle's metrics to these baselines
- Calculate relative position on skill-chance spectrum

## Expected Results

### RSO Analysis

**Hypothesis**: Oracle RSO ≈ 0.4-0.6

**Reasoning**:
1. Dice rolls introduce variance (reduces skill expression)
2. Hidden information limits perfect play
3. But: Many decision points per game (~30 rounds)
4. Resource management rewards planning
5. Combo construction rewards pattern recognition

**Comparison**:
- Poker: RSO ≈ 0.5-0.7 (similar hidden info + variance)
- Magic: RSO ≈ 0.6-0.8 (more complex decisions)
- Backgammon: RSO ≈ 0.4-0.5 (dice rolls, but skill matters)

### Rating Analysis

**Hypothesis**: MAE ≈ 0.1-0.15, Consistency ≈ 70-80%

**Reasoning**:
1. Better AI should win significantly more often
2. But variance from dice/draws prevents 100% win rate
3. Expected rating spread: 30-40 points (Novice to Expert)

**Comparison**:
- Chess: MAE < 0.05, Consistency > 95%
- Poker: MAE ≈ 0.15, Consistency ≈ 70%
- Backgammon: MAE ≈ 0.12, Consistency ≈ 75%

### Deck Type Comparison

**Expected RSO by Deck Type** (highest to lowest skill):

1. **Custom Decks**: RSO ≈ 0.6-0.7
   - Deck construction is a skill component
   - Reduced randomness in deck composition

2. **Draft Formats**: RSO ≈ 0.5-0.6
   - Drafting is a skill
   - Still some randomness in card pool

3. **Monochrome Decks**: RSO ≈ 0.4-0.5
   - Reduced combo complexity
   - More consistent decks

4. **Random Decks**: RSO ≈ 0.3-0.4
   - Maximum variance in deck quality
   - Luck of the draw matters most

## Conclusion

This framework provides a rigorous, research-backed approach to answering "How much skill vs. chance is in Oracle?" The combination of RSO and rating analysis gives complementary perspectives:

- **RSO** measures skill opportunity (how much better outcomes can be with skill)
- **Rating analysis** measures skill expression (how well we can predict outcomes)

Both approaches are feasible to implement within Oracle's existing architecture, requiring only new analysis modules and leveraging already-planned features (rating system, CSV export).

The expected result is that Oracle will fall in the "balanced" category with significant but not dominant skill components, similar to games like Poker and Backgammon. The exact position will depend on deck type and which AI strategies are implemented.
